# Definition of Done (DoD) та Інженерні Стандарти

## 1. Definition of Done (DoD)
Фіча або модуль вважаються завершеними (Done) лише за виконання наступних умов:

1. **Код та Стиль:**
    - Код написаний відповідно до прийнятих конвенцій TypeScript/JavaScript.
    - Успішно пройдені перевірки ESLint та Prettier без будь-яких варнінгів чи помилок.
2. **Перевірки та Тестування:**
    - Локальні git-hooks (Husky + commitlint) успішно відпрацьовують при коміті.
    - Написано юніт-тести для бізнес-логіки (зокрема для `RulesEngineModule`).
    - Наявний мінімальний smoke-тест для перевірки працездатності основного flow.
3. **Архітектура:**
    - Відсутні порушення меж модулів (прямі імпорти між ізольованими доменами заборонені).
    - Всі архітектурні зміни задокументовані у вигляді ADR.
4. **CI/CD:**
    - Створено Pull Request у GitHub.
    - Усі автоматичні перевірки у GitHub Actions пайплайні «зелені».

---

## 2. Чек-лист перевірок перед злиттям (Pull Request Checklist)

- [ ] Формат назви PR відповідає Conventional Commits (наприклад, `feat(registration): add concurrency handling`).
- [ ] Запущено та пройдено локальну збірку та перевірку: `npm run lint && npm run test`.
- [ ] Відсутні нові застарілі або зайві залежності у `package.json`.
- [ ] Публічні API модулів описані та типізовані за допомогою TypeScript/Zod.
- [ ] Оновлено `DEFENSE.md` у разі внесення змін до структури або ключових рішень.
