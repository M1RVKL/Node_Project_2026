
# Definition of Done (DoD) та інженерні стандарти

## 1. Definition of Done

Функціональність або модуль вважаються завершеними (Done), якщо виконані такі умови:

### 1.1. Код та стиль

- Код відповідає прийнятим конвенціям TypeScript/JavaScript.
- Код перевірено за допомогою ESLint.
- Форматування відповідає налаштуванням Prettier.
- Відсутній невикористаний або зайвий код.

### 1.2. Перевірки та тестування

- Перед комітом перевіряються локальні Git Hooks, налаштовані через Husky.
- Для змін у `src/` застосовується lint-staged.
- Для нової бізнес-логіки передбачаються відповідні модульні тести.
- Для інтеграційної логіки передбачаються інтеграційні тести.
- Результати перевірок не повинні вигадуватися або позначатися як успішні без фактичного виконання.

Примітка: на поточному етапі репозиторій не містить налаштованого тестового npm-скрипту та тестового фреймворку.

### 1.3. Архітектура

- Кожен модуль має визначену відповідальність.
- Міжмодульна взаємодія здійснюється через публічні інтерфейси та DTO.
- Заборонені неконтрольовані прямі залежності між внутрішніми компонентами модулів.
- Архітектурні рішення документуються в ADR.
- Зміни моделі даних узгоджуються зі специфікацією `spec.md`.

### 1.4. Документація

- Публічні інтерфейси та важливі архітектурні рішення задокументовані.
- `spec.md` відповідає актуальним вимогам системи.
- У разі зміни архітектури оновлюється відповідний ADR.
- У разі зміни ключових рішень оновлюється `DEFENSE.md`.

### 1.5. Git та командна робота

- Робота над змінами виконується у власній гілці.
- Назви комітів мають відображати суть змін та дотримуватися Conventional Commits.
- Зміни передаються через Pull Request.
- Перед злиттям перевіряється відсутність конфліктів із цільовою гілкою.
- Pull Request повинен містити зрозумілий опис змін.

## 2. Чек-лист перед злиттям (Pull Request Checklist)

- [ ] Зміни виконані в окремій робочій гілці.
- [ ] Назви комітів відповідають Conventional Commits.
- [ ] Код перевірено командою `make lint`.
- [ ] Форматування перевірено та за потреби виправлено через `make format`.
- [ ] Перевірено відсутність зайвих залежностей у `package.json`.
- [ ] Міжмодульні залежності відповідають архітектурним межам.
- [ ] Зміни специфікації та ADR узгоджені між собою.
- [ ] За наявності налаштованого тестового середовища виконані відповідні тести.
- [ ] Документація оновлена відповідно до внесених змін.
- [ ] Створено Pull Request з описом виконаної роботи.
- [ ] Перевірено зміни перед злиттям.

## 3. Поточний стан інструментів

У репозиторії наявні такі інструменти:

- ESLint — перевірка якості коду.
- Prettier — форматування коду.
- Husky — управління Git Hooks.
- lint-staged — запуск перевірок для підготовлених до коміту файлів.

На момент документування:

- У `package.json` визначено лише npm-скрипт `prepare`.
- npm-скрипти `test`, `build` та `dev` не налаштовані.
- Відповідні цілі `test`, `build` та `dev` у Makefile потребують узгодження з майбутньою конфігурацією проєкту.
- Наявність GitHub Actions та автоматизованого CI не підтверджена.

Ці обмеження потрібно враховувати під час перевірки готовності проєкту.

## 4. Правила оновлення стандартів

У разі зміни інструментів, архітектури або процесу розробки цей документ повинен оновлюватися.

Вимоги Definition of Done мають відповідати фактичному стану репозиторію та не повинні описувати непідключені інструменти як уже налаштовані.
