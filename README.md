# 🏓 Платформа для проведення турнірів з настільного тенісу

Інтерактивна система управління змаганнями, побудована за моделлю схожих сайтів з інших дисциплін. Платформа знімає організаційне навантаження з адміністраторів, дозволяючи гравцям самостійно реєструватися, слідкувати за своєю позицією в турнірній сітці та фіксувати результати зіграних матчів у режимі реального часу. 

Проєкт розроблено з фокусом на відмовостійкість, вирішення проблем конкурентного доступу до ресурсів та оптимізацію складних алгоритмічних обчислень.

---

## 🧩 Основні функціональні модулі

### 1. Управління учасниками та реєстрація 📝
* **Опис:** Користувачі мають змогу створювати персональні профілі та подавати заявки на участь у турнірах із жорстко обмеженою кількістю місць.
* **Особливості реалізації:** Процес реєстрації спроєктовано з урахуванням високого навантаження. Система коректно обробляє конкурентні запити (наприклад, коли кілька гравців одночасно претендують на останнє вільне місце) за допомогою суворих рівнів ізоляції транзакцій у нормалізованій базі даних.

### 2. Генерація турнірної сітки 🏆
* **Опис:** Автоматизований розподіл учасників по турнірній сітці з підтримкою форматів Single Elimination та Double Elimination.
* **Особливості реалізації:** Побудова графової структури турніру та розрахунок посіву є найскладнішою обчислювальною задачею системи. Цей механізм виділено в ізольований модуль, що дозволяє незалежно тестувати алгоритм, проводити точне профілювання навантаження та усувати вузькі місця без впливу на інфраструктурний код.

### 3. Проведення матчів та фіксація рахунку ⏱️
* **Опис:** Гравці самостійно вводять результати (рахунок по партіях) зі своїх смартфонів одразу після завершення гри. У разі розбіжностей у введених даних між суперниками, система блокує просування по сітці та генерує конфлікт для судді.
* **Особливості реалізації:** Механізм репортингу побудовано на принципі ідемпотентності. Мережеві збої та випадкові повторні відправки одного й того ж результату не призводять до подвійного зарахування очок чи пошкодження стану турніру.

### 4. Механіка гри ⚖️
* **Опис:** Ядро системи, що відповідає за валідацію рахунку відповідно до офіційних правил настільного тенісу.
* **Особливості реалізації:** Модуль розпізнає перемогу в сеті (11 очок) та обробляє ситуації "більше - меньше" (рахунок 10:10, де вимагається відрив у 2 очки). Вся критична бізнес-логіка повністю відокремлена від бази даних та мережевого шару, що гарантує її абсолютну передбачуваність, стовідсоткове покриття тестами та стійкість до мутацій у коді.

## 🛠 Технологічний стек

Система будується за принципами **Layered Architecture** (з ізоляцією домену) для зручного юніт-тестування та впровадження Dependency Injection (DI).

### ⚙️ Бекенд та Дані
* **Фреймворк:** **Fastify** — забезпечує максимальну продуктивність API, дозволяючи профайлеру шукати боттлнеки саме у бізнес-логіці, а не у фреймворку.
* **База даних:** **PostgreSQL** — надійна реляційна СУБД для роботи зі складними зв'язками турнірів та транзакціями.
* **ORM:** **Prisma** — для швидкого опису схеми, автоматичних міграцій та генерації строгих TypeScript-типів.

### 🖥 Фронтенд
* **Бібліотека:** **React** — для створення динамічного SPA-інтерфейсу (зокрема, інтерактивної турнірної сітки) та виконання вимог щодо оптимізації за метриками Lighthouse / Web Vitals.

### 🧪 Тестування
* **Unit / Інтеграційні:** **Vitest** — швидке тестування з нативною підтримкою TypeScript.
* **Мутаційне:** **StrykerJS** — для виявлення та класифікації виживших мутантів у критичній бізнес-логіці (Rules Engine).
* **E2E:** **Playwright** — для симуляції реальної поведінки користувачів у браузері (наприклад, одночасна фіксація рахунку двома гравцями).

### 📈 Профілювання та Навантаження
* **Генерація навантаження:** **Autocannon** — для збору базових метрик p50/p95/p99 при симуляції типової роботи сервісу.

### 🚀 Інфраструктура та CI/CD
* **CI-пайплайн:** **GitHub Actions** — автоматичний лінтинг, тестування та блокування мерджу в master без проходження всіх перевірок.
* **Стандарти коду:** **Husky + Commitlint** — для жорсткого дотримання специфікації `conventional-commits`.
* **CD / Стейдж:** **Docker Compose + Nginx** — для контейнеризації бази даних, бекенду та роутингу фронтенду на стейдж-сервері з публічним доступом.
